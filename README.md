# 실습 교육 웹사이트 (Training Platform)

Single-course, self-hostable practice-training web app for students. Built with
Next.js 15 (App Router) + TypeScript, Prisma (Cloudflare D1/SQLite), Tailwind CSS,
and iron-session cookies. Files are stored in Supabase Storage. Deploys to
Cloudflare Workers via the OpenNext adapter — local dev also runs against Workers
(via `wrangler`/Miniflare) so the D1 binding is always available.

Students log in with an entry code, work through sequentially-locked steps, and
upload a photo per step (upload auto-advances to the next step). Admins log in
with a shared code + name to view a student roster, manage entry codes, and edit
step content under a pessimistic per-step edit lock.

## Requirements

- Node 20+
- npm
- A Cloudflare account (Workers + D1) — `wrangler login`
- Supabase 프로젝트 (Storage only — 사진 업로드 저장용 `uploads` 버킷). DB는 더 이상
  Supabase/Postgres를 쓰지 않고 Cloudflare D1을 사용한다.

## Setup & Run (local dev via `cf:preview`)

D1 bindings only exist inside the Workers runtime, so local dev runs through
`opennextjs-cloudflare preview` (wrangler/Miniflare-backed) rather than plain
`next dev` for any DB-touching route.

```bash
# 1. Install dependencies (also runs `prisma generate`)
npm install

# 2. Create your .env from the template, then edit the values
cp .env.example .env
#    - ADMIN_CODE: the shared admin login code
#    - SESSION_SECRET: a random string, at least 32 characters
#    - SUPABASE_URL / SUPABASE_SERVICE_ROLE_KEY: Storage 접근용 (서버 전용)

# 3. Also create .dev.vars with the same keys/values as .env (gitignored,
#    read by cf:preview — see "Cloudflare 배포" below)

# 4. Apply the D1 schema to your local D1 file
npm run db:migrate    # wrangler d1 migrations apply aicoding --local

# 5. Seed Course(id=1) + 3 sample steps
npm run db:seed       # wrangler d1 execute aicoding --local --file=d1/seed.sql

# 6. Build once, then run the local preview server
npm run cf:build
npm run cf:preview
```

Open the printed `http://localhost:8787` — choose **학생 입장** (student) or
**관리자 입장** (admin).

- Student entry codes are generated by an admin under **참가 코드**.
- Admin login uses the `ADMIN_CODE` from `.env`/`.dev.vars` plus any name you type.
- Plain `npm run dev` (`next dev`) still works for UI-only iteration that never
  touches the database — any route calling `getDb()` needs `cf:preview`.

## Cloudflare 배포

OpenNext 어댑터로 Cloudflare Workers + D1에 배포한다. 환경변수는 `.env`가 아니라
`wrangler secret`으로 등록한다.

```bash
# 1. Cloudflare 로그인
wrangler login

# 2. 런타임 시크릿 등록
wrangler secret put ADMIN_CODE
wrangler secret put SESSION_SECRET
wrangler secret put SUPABASE_URL
wrangler secret put SUPABASE_SERVICE_ROLE_KEY

# 3. 로컬 프리뷰용 시크릿 파일 (wrangler secret과 별개, .env와 같은 값으로 채우기)
#    .dev.vars는 gitignore 대상 — ADMIN_CODE / SESSION_SECRET /
#    SUPABASE_URL / SUPABASE_SERVICE_ROLE_KEY 를 KEY=value 형식으로 작성

# 4. D1 스키마를 원격 DB에 적용 (최초 1회 / 스키마 변경 시)
npx wrangler d1 migrations apply aicoding --remote

# 5. 빌드 후 Workers 런타임에서 로컬 프리뷰
npm run cf:build
npm run cf:preview

# 6. 프로덕션 배포
npm run cf:deploy
```

## Notes

- Uploaded photos and step images are stored in Supabase Storage (bucket
  `uploads`) and served via `/api/uploads/[...path]`, which validates the storage
  key (allow-listed subdir + UUID filename) behind a session gate.
- Sequential step locking is enforced server-side (a student cannot submit ahead
  of their current step).
- Admin **Reset** on a code force-logs-out the bound student and recycles the
  code back to unused.
- AI grading is intentionally out of scope — a step is complete once its photo
  upload succeeds.
